# IETM ICN附件查询字段错误修复报告

**修复日期**: 2026-09-17  
**问题级别**: P0 (阻塞缺陷)  
**影响范围**: DM预览功能、ICN附件加载

---

## 1. 问题描述

### 1.1 错误现象
用户在预览DM时，后端日志报错：
```
dm.jdbc.driver.DMException: 第1 行附近出现错误:
无效的列名[business_id]
```

### 1.2 调用链
```
DM预览 → DmXmlHelper.replaceIcnPaths() → loadIcnAsBase64() 
→ attachmentService.list(QueryWrapper) → 数据库查询失败
```

### 1.3 根本原因
- **错误查询条件**: 代码使用 `business_id` + `business_type` 字段查询附件
- **实际表结构**: `ietm_attachment` 表中只有 `pid` + `file_type` 字段
- **影响文件数**: 2个文件，2处错误代码

---

### 2.1 受影响功能

2. **ICN附件加载** - IetmIcnManageServiceImpl.loadAttachment() 方法无法正常工作

## 3. 修复方案

### 3.1 字段映射对照
| 错误字段 | 正确字段 | 说明 |
|---------|---------|------|
| `business_id` | `pid` | 父实体ID（ICN的ID） |
| `business_type` | `file_type` | 附件类型（区分实体/相关文件） |

### 3.2 修复内容

#### 修复1: DmXmlHelper.java:419-424
**修复前**:
```java
// 2. 查询附件（使用business_id + business_type，与IetmIcnManageServiceImpl.loadAttachment()一致）

attachmentQw.eq("business_id", icn.getId());
attachmentQw.eq("business_type", "ICN");
attachmentQw.orderByAsc("create_time");
```

**修复后**:
```java
// 2. 查询附件（使用pid字段关联ICN ID）

attachmentQw.eq("file_type", org.jeecg.modules.ietm.common.IetmConstants.FILE_TYPE_ENTITY);

```

## 7. 预防措施

### 7.1 问题根源
- 数据库表结构与实体类定义不一致
- 代码中使用字符串字段名而非类型安全的Lambda表达式

### 7.2 改进建议
1. **使用Lambda表达式**: 
   ```java
   // 推荐方式（类型安全）
   LambdaQueryWrapper<IetmAttachment> qw = new LambdaQueryWrapper<>();
   qw.eq(IetmAttachment::getPid, icnId)
     .eq(IetmAttachment::getFileType, IetmConstants.FILE_TYPE_ENTITY);
   
   // 避免方式（字符串易出错）
   QueryWrapper<IetmAttachment> qw = new QueryWrapper<>();
   qw.eq("pid", icnId)  // 字段名拼写错误在编译期无法发现
     .eq("file_type", ...);
   ```

2. **实体类字段注释**: 为每个字段添加清晰的业务含义注释

3. **集成测试**: 增加端到端测试覆盖DM预览+ICN显示场景
